# SGBM 各参数对视差图的影响

## 1. 先记住一件事

SGBM 没有一组适合所有双目图像的固定参数。参数改变后，通常会同时影响：

- 能够搜索的视差范围；
- 视差图是否平滑；
- 物体边缘是否清楚；
- 黑色无效区域和错误斑块的数量；
- 计算速度。

---

## 2. 参数作用速查表

| 参数 | 主要控制什么 | 数值增大后常见的变化 |
| --- | --- | --- |
| `minDisparity` | 视差搜索的起点 | 整个搜索范围向较大的视差移动 |
| `numDisparities` | 视差搜索范围 | 能搜索更大的视差，但左侧黑带、耗时和误匹配机会通常增加 |
| `blockSize` | 匹配时观察的邻域大小 | 结果更平滑，但物体边缘变厚、细节可能丢失 |
| `P1` | 对小幅视差变化的惩罚 | 视差变化减少，表面更平滑 |
| `P2` | 对大幅视差跳变的惩罚 | 大的视差突变减少，但过大时会抹平物体边界 |
| `disp12MaxDiff` | 左右一致性检查的容许误差 | 越大越宽松，有效像素可能增加，错误点也可能增加 |
| `preFilterCap` | 图像梯度预处理的截断范围 | 保留更多强边缘变化，也可能更容易受噪声影响 |
| `uniquenessRatio` | 对匹配结果“唯一性”的要求 | 越严格，错误匹配通常减少，但黑色空洞增加 |
| `speckleWindowSize` | 要删除的小斑点面积 | 越大，滤除范围越强，小物体也更容易被误删 |
| `speckleRange` | 斑点连通时允许的视差变化 | 越大，不同视差的像素越容易被连成同一块 |
| `mode` | SGBM 的路径聚合方式 | 影响速度和精度，需要通过实测选择 |

---

## 3. 每个参数的详细解释

### 3.1 `minDisparity`：搜索起点

视差通常写成：

```text
视差 = 左图横坐标 - 右图横坐标
```

`minDisparity` 决定从哪个视差值开始搜索。经过正常立体校正的 KITTI 左右图像，通常可以从 `0` 开始。

- 设置正确：搜索范围覆盖真实视差。
- 设置过大：较远物体的小视差可能被排除。
- 设置过小：会搜索不需要的范围，增加计算和误匹配机会。

当前 KITTI 项目建议先固定为 `0`，不把它当作主要调节参数。

### 3.2 `numDisparities`：搜索范围

它表示“最大视差与最小视差之间的范围”，并且必须是 `16` 的倍数。

当 `minDisparity=0` 时：

| 设置值 | 可以搜索的视差 |
| --- | --- |
| `64` | `0～63` 像素 |
| `128` | `0～127` 像素 |
| `256` | `0～255` 像素 |

数值较小：

- 速度更快；
- 左侧无效黑带更窄；
- 错误候选位置更少；
- 但可能无法表示近处物体的大视差。

数值较大：

- 能处理更大的视差，也就是更近的物体；
- 计算时间增加；
- 左侧无效黑带通常变宽；
- 搜索到错误位置的机会增加。

因此它不是越大越好，应当根据多张图片的真实视差范围选择。

### 3.3 `blockSize`：匹配窗口大小

SGBM 不只看一个像素，还会观察它周围的一小块区域。`blockSize` 就是这块区域的边长，必须是大于或等于 `1` 的奇数，通常从 `3、5、7、9` 中测试。

数值较小：

- 能保留车辆边缘、路牌和细小物体；
- 在弱纹理或有噪声的地方可能不稳定；
- 视差图可能出现更多细碎变化。

数值较大：

- 结果通常更平滑；
- 弱纹理区域可能更稳定；
- 前景和背景容易被一个窗口混在一起；
- 车辆轮廓可能膨胀，细小物体可能消失。

### 3.4 `P1` 和 `P2`：平滑惩罚

它们控制相邻像素的视差是否允许突然变化：

- `P1`：惩罚相邻像素之间较小的视差变化；
- `P2`：惩罚较大的视差跳变；
- 必须满足 `P2 > P1`。

OpenCV 给出的常用起点是：

```text
P1 = 8 × 图像通道数 × blockSize²
P2 = 32 × 图像通道数 × blockSize²
```

灰度图的通道数是 `1`。例如 `blockSize=5` 时，可以从 `P1=200、P2=800` 开始。

数值太小：

- 视差图可能破碎、噪点较多；
- 同一平面上的视差变化不稳定。

数值太大：

- 视差图过度平滑；
- 车辆、路沿等真实深度边界可能被抹掉；
- 前景视差可能向背景扩散，或者背景向前景扩散。

调整 `blockSize` 后，应当按照同一公式重新计算 `P1` 和 `P2`，否则比较结果会混入平滑强度变化。

### 3.5 `disp12MaxDiff`：左右一致性检查

算法可以检查“从左图匹配到右图”与“从右图检查回来”的结果是否一致。`disp12MaxDiff` 是允许的最大差异。

- OpenCV 文档写“非正值（如 `-1`、`0`）关闭检查”，但**本项目实测** `-1`、`0`、`1` 三者的视差图结果完全相同，说明在当前 OpenCV 版本中非正值并没有形成单独的“关闭”状态，实际表现与 `1` 相同（详见《阶段一第四步参数组合保留原因》§4）；
- 设置较小的正数：检查严格，错误点减少，但无效区域可能增多；
- 设置较大的正数：检查宽松，有效像素可能增多，但也可能保留错误点。

本项目实际比较了 `-1、0、1、2、5、10、128`。如果结果差别很小，就保留简单、稳定的设置。

### 3.6 `preFilterCap`：预处理截断值

SGBM 会先计算图像横向亮度变化，再把过强的变化截断到指定范围。这个参数主要控制进入匹配过程的边缘信息范围。

- 较小：截断更强，能压制强烈变化，但也可能损失边缘差异；
- 较大：保留更多强边缘信息，也可能保留更多噪声。

它通常不是最先调节的参数。当前项目可先比较 `31` 和 `63`，如果差异很小就固定下来。

### 3.7 `uniquenessRatio`：唯一性要求

一个像素可能在右图中找到多个看起来相似的位置。该参数要求“最佳位置”必须明显优于“第二名”，否则把这个像素判为不可靠。

- 较小：要求宽松，有效像素较多，但容易出现错误斑块；
- 较大：要求严格，错误匹配可能减少，但黑色空洞增加。

OpenCV 建议通常在 `5～15` 范围内尝试。本项目可以比较 `5、10、15`。

### 3.8 `speckleWindowSize`：小斑点过滤

视差图中常出现孤立的小色块，这些小块往往是误匹配。`speckleWindowSize` 决定多大的小连通区域会被当作斑点删除。

- `0`：关闭斑点过滤；
- 数值增大：会删除面积更大的孤立区域，画面看起来更干净；
- 过大：可能把远处车辆、细杆、路牌等真实小结构一起删掉。

OpenCV 建议启用时可从 `50～200` 范围尝试。本项目实际比较了 `0、50、100`（`speckleRange` 取 `1` 和 `2`）。

### 3.9 `speckleRange`：斑点内部允许的视差变化

它决定相邻像素的视差相差多少时，还能被看作同一个连通区域。

- 较小：不同视差更容易被拆成小块，小块更容易被过滤；
- 较大：不同视差更容易连成大块，有些错误区域可能不会再被当作小斑点删除。

OpenCV 通常建议使用 `1` 或 `2`。这个参数只有在启用斑点过滤时才有明显意义。

### 3.10 `mode`：路径聚合模式

常见模式包括：

- `SGBM`：常规模式；
- `SGBM_3WAY`：三方向优化模式，通常速度较快；
- `HH`：更完整的双向路径计算，通常速度较慢；
- `HH4`：另一种四方向模式。

路径更多不等于一定更准确。具体结果会受到场景、其他参数以及 OpenCV 实现影响，必须使用相同图片和相同指标进行实测。

## 4. 参数之间的重要联系

### `blockSize` 与 `P1/P2`

改变 `blockSize` 后，最好根据公式同步计算 `P1/P2`。如果只改窗口、不改平滑惩罚，实验比较的就不只是窗口大小。

### `numDisparities` 与左侧黑带

视差满足 `x右 = x左 - 视差`。左图靠近左边缘的像素在搜索大视差时，对应的右图横坐标会小于 `0`，超出图像范围。因此搜索范围越大，左侧无法正常搜索的区域通常越宽。

### `uniquenessRatio` 与有效像素比例

提高唯一性要求可能减少误匹配，但也会把更多像素判为无效。因此不能只看视差图是否“干净”，还要同时看无效像素比例。

### 斑点过滤与小物体

斑点过滤能清除孤立噪声，也可能清除真实的小型目标。智能车辆场景中，远处车辆和细小交通设施都可能成为受影响对象。

## 5. 实验起点参数（不是最终参数）

下面这组参数只能作为实验起点，不能称为最终参数：

```text
minDisparity       = 0
numDisparities     = 128
blockSize          = 5
P1                 = 200
P2                 = 800
disp12MaxDiff      = 1
preFilterCap       = 63
uniquenessRatio    = 10
speckleWindowSize  = 100
speckleRange       = 2
mode               = SGBM_3WAY
```

阶段一的任务，就是从这个基准出发，通过多场景实验说明为什么保留或修改每个参数。

## 6. 观察视差图时怎样判断问题

| 视差图现象 | 可能相关的参数 |
| --- | --- |
| 左侧黑带很宽 | `numDisparities` 较大 |
| 近处物体碰到视差上限 | `numDisparities` 较小 |
| 车辆边缘很粗、细节消失 | `blockSize`、`P1`、`P2` 可能过大 |
| 路面或墙面非常破碎 | `blockSize`、`P1`、`P2` 可能过小 |
| 出现大量孤立彩色小块 | 唯一性检查较宽松，或斑点过滤较弱 |
| 黑色空洞很多 | 唯一性检查或左右一致性检查可能过严 |
| 小型物体被删掉 | 斑点过滤可能过强 |

只靠肉眼不能确定最终参数。视觉观察用于发现问题，最终判断还要依靠真值误差、多场景稳定性和运行时间。
